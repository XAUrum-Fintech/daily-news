# Customs Duty Tracker

Machine-owned continuation of the `Customs_Duty_Rates.xlsx` Sheet2 event log.
Seeded 2026-09-29 with 62 rows covering 2026-01-13 → 2026-09-17. Nothing here is
hand-edited: every file is regenerated by `tools/build_customs_tracker.py`.

## Official sources — the extraction pattern

| Column group | Source | How to pull |
|---|---|---|
| Gold / silver tariff values | CBIC tariff-value notifications, s.14(2) Customs Act ("Fixation of Tariff Value", amending 36/2001-Customs (N.T.)) | `GET https://taxinformation.cbic.gov.in/api/cbic-notification-msts/fetchNotificationByYearAndCategory?taxId=1000002&category=Non Tariff` — walk page by page (a large size parameter returns truncated results), then `GET /content/pdf/<docFilePath>` per notification and extract TABLE-2: gold USD/10g, silver USD/kg |
| USD/INR import / export | ICEGATE ERAM exchange-rate circulars | `POST https://foservices.icegate.gov.in/cbu/icegateapi/getnotdetails` for the list (`notPublishDate` is the **publication** date), then download each notification's PDF (the detail view is a PDF, not JSON) and read the USD row: import / export rates. The PDF's w.e.f. date is the **effective** date (publication + 1 day) |
| London fix | LBMA | `https://prices.lbma.org.uk/json/gold_pm.json` and `.../silver.json`; `v[0]` is the USD leg. Convention: PM gold fix and silver benchmark **on the notification's published date**, falling back to the most recent earlier quote when that day had no auction. Populated on tariff-value rows only |

**ICEGATE does not publish tariff values** — its notification screen only serves
ERAM exchange rates. Tariff values come from CBIC.

### Provenance verification (2026-09-29)

- **LBMA: 8/8 match.** Sampled fix values on 2026-01-13, 2026-01-30, 2026-03-30,
  2026-09-15 (gold + silver) all equal the sheet exactly.
- **ICEGATE: 3/3 match.** Official PDFs for 02/2026 (91.2/89.5, w.e.f.
  16-01-2026), 14/2026 (95.15/93.45, w.e.f. 08-05-2026), 27/2026 (96.8/95.1,
  w.e.f. 18-09-2026) match the sheet's rates and dates exactly. List endpoint
  returns 71 circulars including all three.
- **CBIC: unreachable from this network** (API returns empty replies; the portal
  SPA never boots). The endpoint + PDF pattern above is documented from the
  operator's own working system; live value verification is pending a reachable
  route.
- **01/2026-Customs (N.T.) is a documented manual override.** Its PDF was
  published with no text layer (text converted to vector outlines), so no parser
  can recover it. Values are hand-entered from the notification's own TABLE-2
  (gold **1485**/10g, silver **2724**/kg, in force 14-01-2026) and the row is
  marked `*` so a hand-entered number never looks like a fetched one.

## Event-log semantics

Customs duty moves whenever **either** a tariff-value notification **or** an
exchange-rate circular lands, so there is **one row per event**, in date order.
Each row carries the full state in force at that moment (tariff value *and*
rate) — that is what makes the duty columns meaningful.

- A tariff-value event carries the last ERAM rate forward; an exchange-rate
  event carries the last tariff values forward.
- Effective date = published date + 1 day.
- Rows only ever grow; history is never rewritten or windowed.
- Duty rate: **15%**.

## Files

- `latest.json` — the full event log, machine-readable.
- `latest.csv` — the same rows with human-readable headers.
- `state.json` — `row_count`, `last_row_published`, `last_row_event`,
  `last_tariff_notification`, `last_eram_notification`, `duty_rate`,
  `updated_at`.
- `tools/build_customs_tracker.py` — append / validate / rebuild. Refuses to
  write anything on validation failure.
- `tools/import_xlsx.py` — one-time seed importer from the .xlsx; kept for
  audit.

### Row schema (`latest.json` rows)

`published`, `effective`, `event` ("Tariff value" | "Exchange rate"),
`tariff_notification` (only on tariff rows), `eram_notification` (only on
exchange rows), `gold_tariff_usd_10g`, `silver_tariff_usd_kg`,
`usd_inr_import`, `usd_inr_export`, `gold_london_fix_usd_oz`,
`gold_tariff_usd_troy_oz`, `silver_london_fix_usd_oz`,
`silver_tariff_usd_troy_oz`, `fix_date`, `gold_value_inr_kg`,
`gold_duty_inr_kg`, `gold_duty_change_inr_kg`, `silver_value_inr_kg`,
`silver_duty_inr_kg`, `silver_duty_change_inr_kg`.

### Formulas (reproduce the sheet exactly)

- `gold_tariff_usd_troy_oz = gold_tariff_usd_10g × 31.1034768 / 10`
- `silver_tariff_usd_troy_oz = silver_tariff_usd_kg × 31.1034768 / 1000`
- `gold_value_inr_kg = gold_tariff_usd_10g × 100 × usd_inr_import`
- `silver_value_inr_kg = silver_tariff_usd_kg × usd_inr_import`
- `gold_duty_inr_kg = gold_value_inr_kg × 0.15` (silver likewise)
- `*_change_inr_kg` = duty − previous row's duty (blank on the first row)

Arithmetic follows the sheet's unrounded float semantics: all 62 seed rows were
independently recomputed from the .xlsx with zero discrepancies.

## Failure behavior

- On any extraction or validation failure, the existing files are left
  untouched and the failure is reported plainly.
- A run that finds no new events stays quiet (no commit).
- A run that appends events regenerates all three data files and commits.
